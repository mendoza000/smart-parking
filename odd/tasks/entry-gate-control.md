## Log
L1. Original request verbatim:

Implementa control bidireccional de la barrera de entrada desde el dashboard Astro de nuestro proyecto Smart Parking.

Actualmente tenemos un Arduino Uno conectado por USB, cuatro botones en D2-D5, un servo SG90 en D9 y una arquitectura Node.js + SerialPort + WebSocket + Astro.

Quiero eliminar la necesidad de un quinto botón físico.

Requisitos:

1. Agrega al dashboard dos controles: "Abrir barrera" y "Cerrar barrera", con una interfaz moderna y una animación visual de la barrera.
2. El frontend enviará comandos estructurados por WebSocket al bridge Node.js.
3. El bridge validará los comandos y los enviará al Arduino mediante SerialPort.
4. El firmware Arduino recibirá comandos `GATE_OPEN` y `GATE_CLOSE` por Serial y controlará el servo del pin D9 con la biblioteca Servo.h.
5. Solo permite abrir la barrera cuando haya al menos un puesto disponible. Esta validación debe realizarse también en Arduino, no únicamente en el frontend.
6. Arduino debe confirmar el estado de la barrera mediante mensajes JSON, incluyendo los cuatro puestos y `gate: "open" | "closed"`.
7. El dashboard debe actualizarse únicamente cuando Arduino confirme el movimiento solicitado.
8. Si Arduino se desconecta, deshabilita los controles de la barrera.
9. Implementa reconocimiento de comandos, manejo de errores y reconexión serial.
10. Evita reinicios innecesarios del Arduino y sincroniza el estado después de una reconexión.
11. Mantén los cuatro botones físicos funcionando con toggle y antirrebote.
12. Al iniciar, el servo debe adoptar una posición cerrada configurable. Utiliza inicialmente 0° para cerrar y 90° para abrir, sin superar los límites mecánicos.
13. No cierres la barrera automáticamente por ahora: el cierre será manual desde el dashboard.
14. No sobrescribas ni cargues automáticamente el firmware al Arduino. Genera el archivo .ino para que pueda subirlo manualmente.

Inspecciona el repositorio actual, reutiliza la arquitectura existente, implementa los cambios, ejecuta las verificaciones y documenta cómo probar la comunicación bidireccional.

L3. Fixed shared contract — protocol worker owns src/lib/protocol.ts, keeping all existing exports/legacy parsing:
- GateState = 'open'|'closed'; GateAction = 'open'|'close'.
- GateCommand = {type:'gate-command',requestId:string,action:GateAction}. IDs match /^[A-Za-z0-9_-]{1,48}$/; only those three keys accepted. parseGateCommand(input:unknown):GateCommand|null validates decoded JSON.
- GateErrorCode = 'INVALID_COMMAND'|'ORIGIN_NOT_ALLOWED'|'ARDUINO_DISCONNECTED'|'NOT_SYNCHRONIZED'|'PARKING_FULL'|'GATE_BUSY'|'SERIAL_WRITE_FAILED'|'ACK_TIMEOUT'|'FIRMWARE_REJECTED'.
- GateResult = {type:'gate-result',requestId:string|null,status:'confirmed'|'rejected',gate:GateState|null,error?:GateErrorCode}. Confirmed requires nonnull safe requestId/gate and no error; rejected requires known error. parseGateResult(input:unknown):GateResult|null validates it.
- Existing Snapshot fields remain required and unchanged. Add optional gate?:GateState|null, gateReady?:boolean, gatePending?:GateAction|null. Legacy snapshots remain valid; supplied new fields are strictly validated, gateReady true requires a known gate.
- ArduinoMessage keeps spots and optional legacy barriers, adds optional gate?:GateState, ack?:'SYNC'|'GATE_OPEN'|'GATE_CLOSE', requestId?:string, error?:'PARKING_FULL'|'GATE_BUSY'|'INVALID_COMMAND'. Old spots-only JSON remains valid. New ACK/error/requestId fields require gate; IDs must be safe. Never coerce invalid gate values.
- toSerialGateCommand(action:GateAction, requestId:string):string|null returns exactly 'GATE_OPEN <id>\n' or 'GATE_CLOSE <id>\n', or null for invalid action/ID. SYNC remains exact 'SYNC\n' for backwards compatibility. getSpotChanges unchanged.

L4. Firmware wire and servo behavior:
- Keep exact SYNC support and four INPUT_PULLUP D2-D5 debounce/toggle behavior; preserve selectable FC-51 continuous mode.
- Accept plain GATE_OPEN/GATE_CLOSE for manual serial tests and optional space+safe ID (up to48chars). Parse with fixed bounded buffers, per-loop byte budget, no dynamic String. Reject malformed/oversized commands with JSON error, without changing occupancy/gate/servo writes.
- Every new firmware JSON includes spots and confirmed gate. Optional ack identifies recognized command (SYNC/GATE_OPEN/GATE_CLOSE), requestId echoes supplied safe ID, error signals rejection. Startup/buttons carry no invented command acknowledgement. - Configurable compile-time bounded angles default closed0/open90, servo attached D9 at setup and closed target applied. Constrain configured angles to declared mechanical min/max within0..180 (default safe range0..90); fail compile or safely reject invalid configuration, never clamp silently to unsafe positions.
- Apply gate command with Servo.write once; retain previous confirmed gate while nonblocking configurable movement interval (default600ms) elapses, keep scanning buttons/Serial. Then change confirmed gate and emit ACK JSON. SG90 has no physical feedback: this is firmware-applied target after settling interval, not proof of an unobstructed physical movement. Document explicitly.

Close always permitted with full parking. No automatic close on capacity change or timer. An already-at-target command may ACK without redundant servo write. Preserve state on rejected input.
